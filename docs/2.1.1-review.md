# KAI 2.1.1 — Full Overview & Review Report

> Joint audit: KAI (architecture, tests, release state) + Code Reviewer (security deep audit, disprove-first verified).
> Date: 2026-11-01 · Base: `aa9572e` · 1343 tests green · tsc / cargo check / clippy / vite build clean.

## Scope

Full codebase review — architecture and trust boundaries — feeding the 2.1.1 release. Security sections were source-traced (not docs) and every serious claim verified by an independent subagent before grading. Nothing was graded from descriptions.

## Architecture

**Design.** Two-process Tauri 2 app: Rust owns every OS boundary (PTY/ConPTY lifecycle, filesystem, git, OS keychain, SSRF-hardened network proxy, MCP bridge, screenshots); the React 19 webview coordinates only. The agent loop is hand-rolled on `streamText` (AI SDK v6) — deliberately not the experimental Agent wrapper — so approval cards, tool redaction, fence markers, and loop detection stay under project control. Modules are self-contained under `src/modules/` with barrel exports; `App.tsx` only wires.

**Trajectory.** Group chat went from the least-stable surface to the most-tested: participant mention routing (with the stable `@coordinator` alias), agent ping-pong chain caps, unified approval cards, persona headless runs with cached fence states, and 40+ regression pins. Recurring root-cause classes are codified in `KAI.md` (unsubscribed imperative reads, arm-then-consume contracts, one-delivery-contract).

**Findings:** none beyond the security section — the architecture held.

## Security review (Code Reviewer)

### Verified clean under attack-pass

- **Approval latch** — `AgentRunBridge.respond()` records denial before forwarding and checks the latch on approve; `approvalLatch.ts` is deny-only with TTL-bounded eviction. Single `addToolApprovalResponse` call site, inside the latched `respond()`; deny→approve races impossible (synchronous check→act). Five bypass vectors attacked by an independent subagent; none landed. Restart safety via `stripIncompleteToolMessages`; the group persona path uses delete-on-first-decision.
- **SSRF gate** (`net.rs`) — classify→pin resolver defeats DNS rebinding; mapped-IPv6, 0.0.0.0/8, 240.0.0.0/4, CGNAT, and AWS metadata all classified; redirect policy re-checks literals and blocks cross-host hops; `danger_accept_invalid_certs` correctly gated on local-only. The `allow_private` carve-outs are user-configured model servers.
- **Central deny floor** (`toolGuards.ts`) — deny-only, fail-closed on guard exception, wraps all tools including MCP (`buildTools → redact → central guard → fence`).
- **Secret-path denylist** (`security.ts`) — NTFS streams, trailing dots/spaces, drive stripping, canonicalize+recheck for symlinks, bidi-override commands blocked.
- **Shell path** — command is base64-embedded; only internal sentinel/base64 is interpolated into the wrapper; sentinel via `rfind` fails safe on truncation.

### SHOULD findings — all three CLOSED (patched in `aa9572e`, verified at source after the fix)

1. **Fence laundering across group hops** — agent-authored text entering another model's context now arrives fenced with the reader's own trusted nonce: coordinator wake fenced at buffer push (`noteParticipantReply`, covering both flush builders), `send_to_project` and routed `@-mentions` fenced for the target session (`agentAuthored` opt on `deliverToParticipant`), persona deliveries fenced with a per persona+group cached fence state that the run's system prompt declares. User sends stay trusted (fence.ts boundary model). No raw agent-authored path back into trusted context remains.
2. **`spawn_command` failure dropped `pair.master` inline under `SPAWN_LOCK`** — the master now goes to a background thread (`begin_teardown`) before the lock is released, matching the documented cleanup contract.
3. **Waiter-thread spawn failure leaked the flusher forever** — the failure arm now drains pending, sends the tail, sets `done`, then drops the session Arc off-thread; the flusher's exit predicate is reachable in all paths. (Benign race: either ordering of tail consumption exits cleanly.)

*Retracted during audit:* the original claim that reader/writer failure paths drop the master inline — they already route through `cleanup_failed_spawn`; documented so it isn't re-raised.

### Open NITs (accepted, deferred to a 2.1.2 hardening pass)

- `respondToApprovalStandalone` audits the approval before the latch may drop it (integrity-only; same in `telegramApprovals.ts`).
- pid-reuse TOCTOU in `PtyJob::create_for` (ms-wide window; the held child handle's pid would be safer).
- `write_shell_script`: predictable `.ps1` names; use `create_new(true)` and delete post-spawn instead of the 60-min TTL sweep.
- `approvalLatch.ts` denial TTL (30 min) vs the "denied forever" comment — fix the comment or the TTL.

### Dependencies

Nothing abandoned or suspicious in `package.json` / `Cargo.toml`. AI SDK v6 / Tauri 2 / React 19 current-line, rustls everywhere. Watch: `imap 3.0.0-alpha.15` is a deliberate pre-release pin (read-only) — eye its stable.

## Recommendations (prioritized)

1. **Cut 2.1.1 with the SHOULD fixes included** — they are in this release (`aa9572e`).
2. **CI source-pin helper** — lint rule flagging file-wide `not.toContain` import pins; they have broken five times under legitimate new consumers. Source pins over JSX/class strings should be `\s*`-regex from day one.
3. **Unified verify loop** — run `cargo check`/`clippy` whenever `src-tauri/**` changes, the same gate as `tsc`; a Rust regression can currently land unnoticed between releases.
4. **Batch the NITs into a 2.1.2 hardening pass** — none is exploitable; all are cheap.
5. **Session store growth** — `kai-sessions.json` is unbounded; size audit + optional per-session pruning in Settings.

## Verdict

**No MUST findings in either half.** The trust boundary core (approval latch, deny floor, SSRF gate, PTY lifecycle contracts, secret denylist) held up under a disprove-first audit. 2.1.1 is clear to cut.
